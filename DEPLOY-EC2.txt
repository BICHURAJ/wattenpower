 1. EC2 INSTANCE (one-time, AWS console)
-------------------------------------------------------------------------------

 - Image: Ubuntu Server 24.04 LTS
 - Type: t3.small (2 GB RAM) recommended. t2/t3.micro (1 GB) works only with
   swap and is slow to build.
 - Disk: 20 GB (the default 8 GB fills up - see section 12).
 - Key pair: keep the .pem file safe.
 - Elastic IP: EC2 -> Elastic IPs -> Allocate -> Associate with the instance,
   so the address never changes when the instance restarts.

 Security group (inbound rules):
   SSH   22  -> My IP only
   HTTP  80  -> prefix list  com.amazonaws.global.cloudfront.origin-facing
                (only CloudFront can reach the server)
   Nothing else. Never open 4000 or 27017.

 Atlas -> Network Access: add the EC2 Elastic IP.

-------------------------------------------------------------------------------
 3. INSTALL DOCKER (one-time)
-------------------------------------------------------------------------------

   curl -fsSL https://get.docker.com | sudo sh
   sudo usermod -aG docker ubuntu
   exit                      # log in again so "docker" works without sudo

 Check:
   docker --version
   docker compose version
   sudo systemctl is-enabled docker     # enabled = starts after reboot


-------------------------------------------------------------------------------
 4. SWAP (one-time, needed on 1 GB servers so the build isn't killed)
-------------------------------------------------------------------------------

   sudo fallocate -l 2G /swapfile
   sudo chmod 600 /swapfile
   sudo mkswap /swapfile
   sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   free -h                   # "Swap:" line should show 2.0Gi

 (Use 4G only if the disk is 20 GB or more - swap takes disk space.)

-------------------------------------------------------------------------------
 6. SERVER-ONLY FILES (not in git - create once, keep a backup)
-------------------------------------------------------------------------------

 cd ~/wattenpower

 6a) docker.env  (SECRETS - never commit, never share)
   cp docker.env.example docker.env
   openssl rand -hex 32                  # copy the output = JWT_SECRET
   nano docker.env

   MONGODB_URI=mongodb+srv://wattenpower:<ATLAS_PASSWORD>@wattenpower0.kzyqoht.mongodb.net/wattenpower?appName=Wattenpower0
   JWT_SECRET=<output of openssl rand -hex 32>
   CORS_ALLOWED_ORIGINS=https://d3cn5j72zptsy8.cloudfront.net

   Notes:
   - Keep "/wattenpower" (the database name) before the "?".
   - Special characters in the password must be URL-encoded:
       @ -> %40   : -> %3A   / -> %2F   ? -> %3F   # -> %23   % -> %25
   - Changing JWT_SECRET signs everyone out (they just log in again).

 6b) Caddyfile  (plain HTTP on port 80; CloudFront provides HTTPS)
   cat > Caddyfile <<'EOF'
   :80 {
       encode gzip
       reverse_proxy web:80 {
           flush_interval -1
       }
   }
   EOF

 6c) docker-compose.prod.yml
   cat > docker-compose.prod.yml <<'EOF'
   services:
     api:
       environment:
         TRUST_PROXY: "3"        # CloudFront -> Caddy -> nginx = 3 proxies
     web:
       ports: !reset []          # not published; Caddy fronts it
     caddy:
       image: caddy:2-alpine
       ports: ["80:80"]
       volumes:
         - ./Caddyfile:/etc/caddy/Caddyfile:ro
         - caddy_data:/data
         - caddy_config:/config
       depends_on: [web]
       restart: unless-stopped
   volumes:
     caddy_data: {}
     caddy_config: {}
   EOF

 Backup these three files (outside the repo folder):
   cp docker.env Caddyfile docker-compose.prod.yml ~/

 7. BUILD AND START (first time)
-------------------------------------------------------------------------------

 Shortcut used everywhere below:
   alias dc='docker compose -f docker-compose.yml -f docker-compose.prod.yml'
   (add that line to ~/.bashrc to keep it)

   cd ~/wattenpower
   dc build api              # build ONE at a time on small servers
   dc build web              # slow on 1 GB servers (5-10 min) - let it finish
   dc up -d
   dc ps

-------------------------------------------------------------------------------
 9. UPDATING AFTER A NEW PUSH TO GITHUB
-------------------------------------------------------------------------------

   cd ~/wattenpower
   git pull                                  # or: git fetch origin && git reset --hard origin/main
   git log --oneline -1                      # confirm the latest commit
   dc build api
   dc build web
   dc up -d --force-recreate web api
   dc ps                                     # web/api "Created ... seconds ago"
   docker image prune -f                     # remove old images, frees disk

 IMPORTANT: "dc restart" or "dc up -d" WITHOUT building keeps the OLD code.
 Always build, then --force-recreate.

 CloudFront normally shows the new version straight away (pages aren't cached).
 If not: CloudFront -> distribution -> Invalidations -> Create -> /*
 Browsers keep old tab icons for a long time - check in Incognito.

 10. CLOUDFRONT SETTINGS (reference)
-------------------------------------------------------------------------------

 Origin:
   Origin domain ... ec2-13-60-214-86.eu-north-1.compute.amazonaws.com
   Protocol ........ HTTP only
   HTTP port ....... 80

 Behaviours (all: Viewer protocol = Redirect HTTP to HTTPS):
   Default (*) ... methods GET,HEAD,OPTIONS,PUT,POST,PATCH,DELETE
                   cache policy CachingDisabled
                   origin request policy AllViewerExceptHostHeader
   /api/* ........ same as Default (never cache API, pass login header)
   /assets/* ..... GET,HEAD, cache policy CachingOptimized (fast static files)

 Own domain later: ACM certificate in us-east-1 -> add as Alternate domain
 name -> CNAME to the cloudfront.net name -> update CORS_ALLOWED_ORIGINS.

 12. PROBLEMS WE HIT AND THE FIXES
-------------------------------------------------------------------------------

 "signal: killed" / "failed to execute bake: signal: killed" during build
   -> Out of memory. Add swap (section 4), build api and web separately,
      or use a t3.small.

 "no space left on device"
   -> Disk full (8 GB default + swap + images). Resize the disk:
      EC2 -> Instance -> Storage -> Volume -> Actions -> Modify volume -> 20 GB
      then on the server:
        lsblk
        sudo growpart /dev/nvme0n1 1        (or /dev/xvda 1)
        sudo resize2fs /dev/nvme0n1p1       (or /dev/xvda1)
        df -h /
      Clean up:
        docker system prune -a -f
        docker builder prune -a -f
        sudo apt-get clean
        sudo journalctl --vacuum-size=100M

 CloudFront "504 Gateway Timeout"
   -> CloudFront can't reach EC2. Check: origin protocol = HTTP only, port 80;
      security group allows the CloudFront prefix list on port 80;
      the instance IP hasn't changed (use an Elastic IP).

 Browser "ERR_SSL_PROTOCOL_ERROR" on the IP address
   -> HTTPS doesn't work on a bare IP. Use the CloudFront https address.
      Caddyfile must start with ":80 {" (not the IP).

 Site shows old version / old logo
   -> Containers weren't rebuilt. Run section 9 (build + --force-recreate).
      "dc ps" shows an image name like "sha256:..." = running an old image.

 API keeps restarting - "dc logs api" shows:
   bad auth : authentication failed -> wrong Atlas password in docker.env
   ... timed out                      -> server IP not in Atlas Network Access
   [config] JWT_SECRET is not set     -> docker.env missing or empty
   [config] CORS_ALLOWED_ORIGINS ...  -> must be the exact https address, no "/"

 git pull: "Permission denied (publickey)"
   -> Deploy key missing (section 5).

 git pull: "local changes would be overwritten"
   -> git stash ; git pull ; git stash pop
      (or git reset --hard origin/main - docker.env, Caddyfile and
       docker-compose.prod.yml are safe, they are not in git)
